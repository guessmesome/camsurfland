# CamSurf: аналитика

Закрытая таблица: `/analytics`. Вход через поля логина и пароля, защищённая cookie на 8 часов.
Данные берутся из Vercel Web Analytics этого проекта; сбор начинается после публикации.

## Экраны

1. Знакомство
2. Ввод почты
3. Подтверждение 18+

## События

- `/onboarding/1`…`/onboarding/3` — просмотры фактически открытых экранов.
- `cta_click` — основная кнопка, `back_click` — внутренняя кнопка «Назад», если она есть.
- `screen_time_1`…`screen_time_3` — видимое время; скрытая вкладка не учитывается.
- `email_started`, `email_entered` — начало ввода и корректный формат, по одному разу за загрузку, только на экране 2.
- `email_submit` — принятая отправка корректной формы (попытки после ошибки считаются отдельно).
- `outbound_redirect` — браузер принял переход по полученной ссылке. Не подтверждает загрузку стороннего сайта.
- `returning_redirect` — существующий автоматический переход повторного посетителя, если предусмотрен лендингом.
- `offer_return` — возврат после ухода на оффер через историю браузера/BFCache; обычная перезагрузка не считается возвратом.
- `redirect_error` — не удалось получить или открыть ссылку.

Сам email, параметры рекламного перехода и URL оффера в аналитику не передаются. Географию определяет Vercel.
Отчёт поддерживает даты до 31 дня за запрос, фильтр страны и среды; уникальность посетителей определяется Vercel.
Среднее время = видимое время / просмотры. При неполных агрегатах отображается предупреждение.
Возвраты и доставка событий зависят от браузера и блокировщиков; это не подтверждение действий на стороне оффера.

## Vercel

Нужны Web Analytics и тариф с custom events. Серверные переменные:
`ANALYTICS_USERNAME`, `ANALYTICS_PASSWORD`, `VERCEL_ANALYTICS_TOKEN`,
`VERCEL_ANALYTICS_PROJECT_ID`, `VERCEL_ANALYTICS_TEAM_ID`.
Секреты только в Vercel, не в репозитории. Файлы доступов выдаются отдельно.
`npm run build` копирует только публичный фронтенд и медиа в `public/`;
шаблоны отчёта и серверная логика обслуживаются защищённой функцией.
